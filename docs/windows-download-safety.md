# Windows download safety

## Current signing status

Codex Quota Dot's current Windows installer, MSI, and portable executable are **not code-signed**. An unsigned executable has no verified publisher identity and may trigger Microsoft Defender SmartScreen, antivirus reputation checks, or heuristic detections, especially while the project and its download history are new.

A warning does not by itself prove that a file is malicious, but it must not be dismissed automatically as a false positive. Do not disable antivirus protection or add an exclusion just to run Codex Quota Dot.

## Download from the canonical source

Use only the project's [GitHub Releases](https://github.com/Silvren/codex-quota-dot/releases/latest) page. Each Windows asset has a neighboring `.sha256` file generated by the release workflow.

## Verify SHA-256 on Windows

Place the downloaded asset and its `.sha256` file in the same directory, open PowerShell in that directory, and run:

```powershell
$file = "Codex-Quota-Dot-v0.2.1-windows-x64-setup.exe"
$actual = (Get-FileHash -LiteralPath $file -Algorithm SHA256).Hash.ToLower()
$expected = ((Get-Content -LiteralPath "$file.sha256" -Raw) -split '\s+')[0].ToLower()
$actual
$expected
$actual -eq $expected
```

The last line must be `True`. A matching hash proves that the file is byte-for-byte identical to the artifact published by the GitHub release workflow; it does not replace malware scanning or code signing.

## Report a warning or detection

Open a [Windows security warning report](https://github.com/Silvren/codex-quota-dot/issues/new?template=security_warning.yml) and include:

- exact release version and asset file name;
- the URL from which the file was downloaded;
- calculated SHA-256;
- security product and version;
- exact threat or detection name;
- whether the warning appeared on download, installation, or first launch;
- a screenshot with personal paths and account information removed.

If you have evidence of an actual vulnerability rather than an antivirus warning, use the repository's private GitHub Security Advisory channel described in [`SECURITY.md`](../SECURITY.md).

## Long-term mitigation

The project intends to add Windows code signing when a suitable certificate and protected release-signing workflow are available. Hashes and public CI provenance remain useful after signing, but signing is the appropriate long-term way to establish publisher identity and improve Windows reputation.
